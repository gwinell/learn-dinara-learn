## 1. Что делает эта программа

Это консольная реализация **игры «Жизнь»** (The Game of Life) Джона Конвея.

- Поле размером **80 клеток в ширину** и **25 клеток в высоту**.
- Клетки живые (`*`) и мёртвые (пробел).
- Поле «замкнуто само на себя»: уходя за правый край, попадаешь на левый, а за нижний — на верхний.
- Начальное состояние задаётся через `stdin` (стандартный ввод). Обычно это делается перенаправлением из файла.
- Управление:
  - `A` — ускорить (задержка между поколениями уменьшается).
  - `Z` — замедлить (задержка увеличивается).
  - `Пробел` или `Q` — выход.
- Графика рисуется в терминале с помощью библиотеки **ncurses**.

## 2. Как запустить

### Скомпилировать

```bash
gcc src/game_of_life.c -o src/game_of_life -lncurses
```

Здесь:
- `gcc` — компилятор языка C.
- `src/game_of_life.c` — файл с исходным кодом.
- `-o src/game_of_life` — имя получившейся программы.
- `-lncurses` — подключить библиотеку ncurses (буква `l` от слова *link*).

### Запустить с файлом начального состояния

```bash
./src/game_of_life < src/initial_state_1.txt
```

Знак `<` означает **перенаправление ввода**: программа будет читать не с клавиатуры, а из файла `initial_state_1.txt`.

## 4. Ключевые понятия, которые нужно знать перед чтением кода

### 4.1. `stdin` и `stdout`

Если вы знаете `printf` и `scanf`, то уже работали с этими потоками:

- `printf` пишет в **`stdout`** — стандартный вывод. Обычно это экран.
- `scanf` читает из **`stdin`** — стандартный ввод. Обычно это клавиатура.

Но `stdin` можно перенаправить. Команда:

```bash
./game_of_life < file.txt
```

говорит операционной системе: «Вместо клавиатуры подавай в программу содержимое файла `file.txt`».

### 4.2. Массивы

Массив — это набор переменных одного типа, расположенных подряд в памяти.

```c
int a[5];
```

Это 5 целых чисел: `a[0]`, `a[1]`, `a[2]`, `a[3]`, `a[4]`.

Массив может быть многомерным:

```c
int field[25][80];
```

Это таблица 25 строк и 80 столбцов. `field[3][7]` — клетка в 4-й строке, 8-м столбце (нумерация с нуля).

### 4.3. Структуры (`struct`)

Структура — это способ объединить несколько переменных в одну логическую сущность.

```c
struct Field {
    int cells[25][80];
};
```

Теперь `struct Field` — это тип данных, который содержит внутри себя двумерный массив `cells`.

Можно создать переменную этого типа:

```c
struct Field field;
```

И обращаться к массиву внутри неё:

```c
field.cells[3][7] = 1;
```

### 4.4. Указатели

Указатель — это переменная, которая хранит **адрес** другой переменной в памяти.

```c
int x = 10;
int* p = &x;  // p хранит адрес x
```

Оператор `&` берёт адрес. Оператор `*` позволяет работать с данными по адресу:

```c
*p = 20;  // теперь x == 20
```

Когда функция принимает указатель, она может изменить оригинальную переменную:

```c
static void make_zero(int* p) {
    *p = 0;
}

int x = 5;
make_zero(&x);  // x стало 0
```

В нашем коде указатели используются, чтобы функции могли изменять поле `struct Field`, которое объявлено в `main`.

### 4.5. `static`

Ключевое слово `static` перед функцией означает, что функция видна только внутри этого файла. Другие файлы не могут её вызвать.

Пример:

```c
static int sum(int a, int b);

int main() {
    int x = sum(2, 3);
    return 0;
}

static int sum(int a, int b) {
    return a + b;
}
```

В нашем коде все вспомогательные функции объявлены как `static`, потому что они используются только в `game_of_life.c`. Это хорошая практика: она ограничивает видимость функций и помогает статическим анализаторам, таким как `cppcheck`, лучше понимать код.

### 4.6. `const`

Ключевое слово `const` означает «только для чтения».

```c
const struct Field* field
```

Это указатель на `struct Field`, который функция **не будет изменять**. Она может читать `field->cells`, но не может их менять.

## 5. Разбор кода

### 5.1. Подключение заголовочных файлов

```c
#include <ncurses.h>
#include <stdio.h>
#include <unistd.h>
```

- `ncurses.h` — библиотека для управления текстовым экраном терминала.
- `stdio.h` — стандартный ввод/вывод (`printf`, `scanf`, `fgets`, `freopen`).
- `unistd.h` — функция `usleep` (пауза в микросекундах).

### 5.2. Константы через `#define`

```c
#define FIELD_WIDTH 80
#define FIELD_HEIGHT 25
#define MIN_DELAY 10000
#define MAX_DELAY 500000
#define INITIAL_DELAY 100000
#define DELAY_STEP 10000
```

`#define` заменяет имя на значение ещё до компиляции. Например, везде, где компилятор видит `FIELD_WIDTH`, он подставляет `80`.

Это удобно: если захочется изменить размер поля, достаточно поменять одну строчку.

### 5.3. Структура поля

```c
struct Field {
    int cells[FIELD_HEIGHT][FIELD_WIDTH];
};
```

Создаём свой тип данных `struct Field`. Внутри него — двумерный массив `cells` размером 25×80. Каждая клетка хранит целое число:
- `0` — мёртвая клетка.
- `1` — живая клетка.

### 5.4. Объявления функций (прототипы)

```c
static int count_neighbors(const struct Field* field, int row, int col);
static void update_field(const struct Field* field, struct Field* new_field);
static void copy_field(const struct Field* src, struct Field* dest);
static void read_initial_state(struct Field* field);
static void print_field(const struct Field* field);
static int init_ncurses();
static void cleanup_ncurses();
static int handle_input(int delay, int* running);
static void game_loop(struct Field* field, struct Field* next_field);
```

Здесь сообщается компилятору: «Вот функции, которые будут определены позже». Это позволяет вызывать их из `main`, хотя реализация находится внизу файла.

После каждого имени функции в скобках указаны параметры, которые она принимает. Например:

```c
static void print_field(const struct Field* field);
```

- `static` — функция видна только внутри этого файла.
- `void` — функция ничего не возвращает.
- `print_field` — имя функции.
- `const struct Field* field` — принимает указатель на `struct Field`, только для чтения.

### 5.5. Функция `main`

```c
int main() {
    struct Field field = {0};
    struct Field next_field = {0};
    int error = 0;
    read_initial_state(&field);
    if (freopen("/dev/tty", "r", stdin) == NULL) {
        error = 1;
    }
    if (error == 0) {
        error = init_ncurses();
    }
    if (error == 0) {
        game_loop(&field, &next_field);
        cleanup_ncurses();
    }
    return error;
}
```

Разберём по шагам.

#### 5.5.1. Создание полей

```c
struct Field field = {0};
struct Field next_field = {0};
```

Создаём две переменные типа `struct Field`. `{0}` означает, что весь массив заполняется нулями. То есть оба поля изначально полностью мёртвые.

Зачем два поля? Одно (`field`) хранит текущее поколение, другое (`next_field`) — следующее. Правила игры требуют, чтобы все клетки обновлялись одновременно. Поэтому мы не можем менять текущее поля прямо во время подсчёта: сначала вычисляем всё новое поколение в отдельном поле, а потом копируем его на место старого.

#### 5.5.2. Чтение начального состояния

```c
read_initial_state(&field);
```

Функции передаётся **адрес** переменной `field`. Значок `&` означает «взять адрес». Функция `read_initial_state` заполнит это поле клетками, прочитанными из `stdin`.

#### 5.5.3. Переключение `stdin` на терминал

```c
if (freopen("/dev/tty", "r", stdin) == NULL) {
    error = 1;
}
```

Здесь происходит важный трюк.

Когда программа запускается так:

```bash
./game_of_life < file.txt
```

её `stdin` — это не клавиатура, а файл `file.txt`. Мы уже прочитали начальное состояние из этого файла. Но дальше нам нужно читать нажатия клавиш для управления. Клавиатура связана с терминалом, а не с файлом.

`/dev/tty` — это специальный файл, который представляет собой текущий терминал пользователя.

Функция `freopen` открывает `/dev/tty` для чтения (`"r"`) и связывает его с потоком `stdin`. Теперь `stdin` снова читает с клавиатуры.

Если `freopen` не смогла открыть терминал (например, программа запущена без терминала), она возвращает `NULL`. В этом случае в переменную `error` записывается `1`.

#### 5.5.4. Инициализация ncurses

```c
if (error == 0) {
    error = init_ncurses();
}
```

Если на предыдущем шаге не было ошибки, инициализируем библиотеку `ncurses`. Функция `init_ncurses` возвращает `0`, если всё хорошо, и `1`, если терминал слишком маленький.

#### 5.5.5. Игровой цикл

```c
if (error == 0) {
    game_loop(&field, &next_field);
    cleanup_ncurses();
}
```

Если всё в порядке, запускаем основной игровой цикл. После выхода из него вызываем `cleanup_ncurses`, чтобы корректно завершить работу с терминалом.

#### 5.5.6. Возврат кода ошибки

```c
return error;
```

Программа возвращает операционной системе `0`, если всё прошло успешно, и `1`, если была ошибка. Это стандартная договорённость в C.

## 6. Подробный разбор каждой функции

### 6.1. `count_neighbors` — подсчёт соседей

```c
static int count_neighbors(const struct Field* field, int row, int col) {
    int count = 0;
    for (int dr = -1; dr <= 1; dr++) {
        for (int dc = -1; dc <= 1; dc++) {
            if (dr != 0 || dc != 0) {
                int r = (row + dr + FIELD_HEIGHT) % FIELD_HEIGHT;
                int c = (col + dc + FIELD_WIDTH) % FIELD_WIDTH;
                count += field->cells[r][c];
            }
        }
    }
    return count;
}
```

Функция считает, сколько живых соседей у клетки `(row, col)`.

#### Внешние циклы

```c
for (int dr = -1; dr <= 1; dr++) {
    for (int dc = -1; dc <= 1; dc++) {
```

`dr` и `dc` — это смещение по строке и столбцу. Они принимают значения `-1`, `0`, `1`. Вместе это перебирает все 9 клеток вокруг данной: слева сверху, сверху, справа сверху, слева, сама клетка, справа, слева снизу, снизу, справа снизу.

#### Пропуск самой клетки

```c
if (dr != 0 || dc != 0) {
```

Когда `dr == 0` и `dc == 0`, это сама клетка `(row, col)`. Её не нужно считать соседом самой себе, поэтому пропускаем.

#### Тороидальность (замкнутость поля)

```c
int r = (row + dr + FIELD_HEIGHT) % FIELD_HEIGHT;
int c = (col + dc + FIELD_WIDTH) % FIELD_WIDTH;
```

Здесь реализован эффект «поле замкнуто само на себя».

Оператор `%` — это остаток от деления. Если клетка находится у края:

- Для верхнего края (`row == 0`) и смещения `-1` получаем `0 - 1 + 25 = 24`, и `24 % 25 = 24`. То есть переходим в самую нижнюю строку.
- Для нижнего края (`row == 24`) и смещения `+1` получаем `24 + 1 + 25 = 50`, и `50 % 25 = 0`. Переходим в самую верхнюю строку.

Аналогично работает по горизонтали.

Добавление `FIELD_HEIGHT` перед `%` нужно, чтобы не получить отрицательное число. В C остаток от деления отрицательного числа может быть отрицательным, что привело бы к выходу за границы массива.

#### Подсчёт

```c
count += field->cells[r][c];
```

`field->cells[r][c]` — это значение клетки (`0` или `1`). Если клетка живая, прибавляется `1`. В результате `count` содержит количество живых соседей.

### 6.2. `update_field` — вычисление следующего поколения

```c
static void update_field(const struct Field* field, struct Field* new_field) {
    for (int row = 0; row < FIELD_HEIGHT; row++) {
        for (int col = 0; col < FIELD_WIDTH; col++) {
            int neighbors = count_neighbors(field, row, col);
            int alive = field->cells[row][col];
            int next = 0;
            if (alive && (neighbors == 2 || neighbors == 3)) {
                next = 1;
            } else if (!alive && neighbors == 3) {
                next = 1;
            }
            new_field->cells[row][col] = next;
        }
    }
}
```

Эта функция применяет правила игры «Жизнь» ко всем клеткам.

#### Циклы

```c
for (int row = 0; row < FIELD_HEIGHT; row++) {
    for (int col = 0; col < FIELD_WIDTH; col++) {
```

Перебираем все клетки поля.

#### Подсчёт соседей и текущее состояние

```c
int neighbors = count_neighbors(field, row, col);
int alive = field->cells[row][col];
```

- `neighbors` — сколько живых соседей.
- `alive` — жива ли сама клетка (`1` или `0`).

#### Правила игры

```c
int next = 0;
if (alive && (neighbors == 2 || neighbors == 3)) {
    next = 1;
} else if (!alive && neighbors == 3) {
    next = 1;
}
```

Правила Конвея:
1. Живая клетка с 2 или 3 соседями остаётся живой.
2. Живая клетка с менее 2 или более 3 соседей умирает.
3. Мёртвая клетка с ровно 3 соседями становится живой.

Переменная `next` изначально `0` (клетка мёртвая). Она становится `1` только если выполняется одно из двух условий выше.

#### Запись результата

```c
new_field->cells[row][col] = next;
```

Результат записывается во второе поле, чтобы не повлиять на подсчёты для остальных клеток текущего поколения.

### 6.3. `copy_field` — копирование поля

```c
static void copy_field(const struct Field* src, struct Field* dest) {
    for (int row = 0; row < FIELD_HEIGHT; row++) {
        for (int col = 0; col < FIELD_WIDTH; col++) {
            dest->cells[row][col] = src->cells[row][col];
        }
    }
}
```

Просто копирует содержимое одного поля в другое. После вычисления `next_field` в `update_field`, эта функция переносит его в `field`, чтобы на следующем шаге цикла `field` стало текущим поколением.

### 6.4. `read_initial_state` — чтение начального состояния

```c
static void read_initial_state(struct Field* field) {
    char line[FIELD_WIDTH + 2];
    for (int row = 0; row < FIELD_HEIGHT; row++) {
        for (int col = 0; col < FIELD_WIDTH; col++) {
            field->cells[row][col] = 0;
        }
    }
    for (int row = 0; row < FIELD_HEIGHT && fgets(line, sizeof(line), stdin); row++) {
        for (int col = 0; col < FIELD_WIDTH && line[col] != '\0' && line[col] != '\n'; col++) {
            if (line[col] == '1' || line[col] == '*') {
                field->cells[row][col] = 1;
            }
        }
    }
}
```

#### Обнуление поля

```c
char line[FIELD_WIDTH + 2];
for (int row = 0; row < FIELD_HEIGHT; row++) {
    for (int col = 0; col < FIELD_WIDTH; col++) {
        field->cells[row][col] = 0;
    }
}
```

Сначала всё поле заполняется мёртвыми клетками (`0`). Это нужно на случай, если входной файл короче 25 строк.

Массив `line` нужен для временного хранения одной строки из файла. Размер `FIELD_WIDTH + 2` — 80 символов данных + символ новой строки `\n` + завершающий ноль `\0`.

#### Чтение строк

```c
for (int row = 0; row < FIELD_HEIGHT && fgets(line, sizeof(line), stdin); row++) {
```

Цикл читает строки из `stdin` с помощью `fgets`.

`fgets(line, sizeof(line), stdin)` читает одну строку (до новой строки или конца файла) в массив `line`. Функция возвращает указатель на `line`, если чтение успешно, или `NULL`, если достигнут конец файла.

Условие цикла состоит из двух частей:
- `row < FIELD_HEIGHT` — прочитано менее 25 строк.
- `fgets(...)` — чтение прошло успешно.

Если файл закончился раньше 25 строк, цикл остановится.

#### Обработка символов в строке

```c
for (int col = 0; col < FIELD_WIDTH && line[col] != '\0' && line[col] != '\n'; col++) {
    if (line[col] == '1' || line[col] == '*') {
        field->cells[row][col] = 1;
    }
}
```

Перебираем символы строки:
- `col < FIELD_WIDTH` — не выходим за пределы поля.
- `line[col] != '\0'` — не дошли до конца строки.
- `line[col] != '\n'` — не дошли до символа новой строки.

Если символ равен `'1'` или `'*'`, клетка становится живой (`1`). Все остальные символы считаются мёртвыми клетками.

### 6.5. `print_field` — отрисовка поля

```c
static void print_field(const struct Field* field) {
    clear();
    for (int row = 0; row < FIELD_HEIGHT; row++) {
        for (int col = 0; col < FIELD_WIDTH; col++) {
            char ch = field->cells[row][col] ? '*' : ' ';
            mvaddch(row, col, ch);
        }
    }
    refresh();
}
```

Эта функция рисует поле в терминале с помощью `ncurses`.

```c
clear();
```

Очищает экран терминала.

```c
char ch = field->cells[row][col] ? '*' : ' ';
```

Тернарный оператор `? :` — это сокращённая форма `if-else`. Если клетка живая (`1`), символ `'*'`, иначе пробел `' '`.

```c
mvaddch(row, col, ch);
```

`mvaddch` — функция `ncurses`. Она ставит символ `ch` на экране в позицию `(row, col)`.

```c
refresh();
```

Выводит на экран всё, что было нарисовано в буфере. Без `refresh()` изменения не появятся на экране.

### 6.6. `init_ncurses` — инициализация экрана

```c
static int init_ncurses() {
    int result = 0;
    initscr();
    noecho();
    cbreak();
    nodelay(stdscr, TRUE);
    curs_set(0);
    if (LINES < FIELD_HEIGHT || COLS < FIELD_WIDTH) {
        endwin();
        result = 1;
    }
    return result;
}
```

Функция настраивает терминал для работы `ncurses`.

```c
initscr();
```

Инициализирует экран. С этого момента `printf`/`scanf` лучше не использовать — управление экраном берёт на себя `ncurses`.

```c
noecho();
```

Отключает автоматический вывод нажатых клавиш на экран. Без этого каждое нажатие `A`, `Z`, `Q` дублировалось бы на экране.

```c
cbreak();
```

Переводит терминал в режим, при котором ввод обрабатывается посимвольно. Без этого программа ждала бы нажатия Enter после каждой клавиши.

```c
nodelay(stdscr, TRUE);
```

Делает функцию `getch()` **неблокирующей**. Если пользователь ничего не нажал, `getch()` сразу возвращает специальное значение `ERR`, и программа продолжает работать. Без этого программа зависла бы в ожидании клавиши.

```c
curs_set(0);
```

Прячет мигающий курсор.

```c
if (LINES < FIELD_HEIGHT || COLS < FIELD_WIDTH) {
    endwin();
    result = 1;
}
```

`LINES` и `COLS` — это переменные `ncurses`, которые содержат размер терминала. Если терминал меньше 25×80, программа завершает `ncurses` (`endwin()`) и возвращает ошибку (`1`).

### 6.7. `cleanup_ncurses` — завершение работы с экраном

```c
static void cleanup_ncurses() { endwin(); }
```

Функция `endwin()` возвращает терминал в обычный режим. Без неё после выхода из программы экран может остаться в странном состоянии.

### 6.8. `handle_input` — обработка нажатий клавиш

```c
static int handle_input(int delay, int* running) {
    int result = delay;
    int ch = getch();
    if (ch == ' ' || ch == 'q' || ch == 'Q') {
        *running = 0;
    } else if ((ch == 'a' || ch == 'A') && result > MIN_DELAY) {
        result -= DELAY_STEP;
    } else if ((ch == 'z' || ch == 'Z') && result < MAX_DELAY) {
        result += DELAY_STEP;
    }
    return result;
}
```

Функция обрабатывает управление.

```c
int ch = getch();
```

`getch()` — функция `ncurses`, которая читает одну нажатую клавишу. Благодаря `nodelay`, если ничего не нажато, возвращается `ERR` (обычно `-1`).

```c
if (ch == ' ' || ch == 'q' || ch == 'Q') {
    *running = 0;
}
```

Если нажат пробел, `q` или `Q`, через указатель `running` записывается `0`. В `game_loop` переменная `running` станет `0`, и цикл завершится.

```c
else if ((ch == 'a' || ch == 'A') && result > MIN_DELAY) {
    result -= DELAY_STEP;
}
```

Если нажата `A`, уменьшаем задержку на `DELAY_STEP` (10 000 микросекунд), но не ниже `MIN_DELAY`. Меньшая задержка = быстрее игра.

```c
else if ((ch == 'z' || ch == 'Z') && result < MAX_DELAY) {
    result += DELAY_STEP;
}
```

Если нажата `Z`, увеличиваем задержку, но не выше `MAX_DELAY`. Большая задержка = медленнее игра.

### 6.9. `game_loop` — игровой цикл

```c
static void game_loop(struct Field* field, struct Field* next_field) {
    int delay = INITIAL_DELAY;
    int running = 1;
    while (running) {
        print_field(field);
        update_field(field, next_field);
        copy_field(next_field, field);
        usleep(delay);
        delay = handle_input(delay, &running);
    }
}
```

Это сердце программы.

```c
int delay = INITIAL_DELAY;
```

Начальная задержка между поколениями — 100 000 микросекунд (0.1 секунды).

```c
int running = 1;
while (running) {
```

Бесконечный цикл, который работает, пока `running` не станет `0`.

Внутри цикла происходит:

1. ```c
   print_field(field);
   ```
   Рисуем текущее поле на экране.

2. ```c
   update_field(field, next_field);
   ```
   Вычисляем следующее поколение во втором поле.

3. ```c
   copy_field(next_field, field);
   ```
   Копируем новое поколение в основное поле.

4. ```c
   usleep(delay);
   ```
   Делаем паузу на `delay` микросекунд, чтобы анимация была видна.

5. ```c
   delay = handle_input(delay, &running);
   ```
   Проверяем, нажал ли пользователь клавишу, и обновляем задержку или флаг выхода.

## 7. Почему код написан именно так

### 7.1. Два поля вместо одного

Игра требует, чтобы все клетки обновлялись одновременно. Если менять `field` прямо во время подсчёта соседей, результат будет неправильным: соседи уже изменённых клеток повлияют на подсчёт для следующих.

Поэтому используется «двойная буферизация»:
- `field` — текущее поколение (только читаем).
- `next_field` — следующее поколение (записываем).
- После обработки `next_field` копируется в `field`.

### 7.2. Почему функции `static`

Все вспомогательные функции объявлены как `static`, потому что они используются только в этом файле. Это ограничивает их видимость и помогает статическим анализаторам (например, `cppcheck`) понимать код.

Без `static` функции получали бы «внешнее связывание»: другие файлы могли бы их вызывать. Поскольку мы пишем однофайловую программу, внешнее связывание не нужно, и `static` позволяет избежать лишних предупреждений анализаторов.

### 7.3. Почему используются указатели

`struct Field` занимает в памяти `25 * 80 * 4 = 8000` байт (если `int` 4 байта). Если передавать его по значению, компилятор будет копировать все 8000 байт при каждом вызове функции. Указатель занимает 8 байт (на 64-битной системе), поэтому передача по указателю быстрее и экономит память.

Кроме того, функции `read_initial_state`, `update_field`, `copy_field` и `game_loop` должны **изменять** поля. Без указателей они бы работали с копиями, и оригинальные поля в `main` не изменились бы.

### 7.4. Почему `freopen("/dev/tty", "r", stdin)`

Программа читает начальное состояние из `stdin`. Когда запуск происходит через `program < file.txt`, `stdin` связан с файлом, а не с клавиатурой.

Но `ncurses` для чтения клавиш тоже использует `stdin` (через управляющий терминал). Если не переключить `stdin` обратно на терминал, управление работать не будет.

`/dev/tty` — это универсальный способ получить доступ к текущему терминалу.

## 9. Правила игры «Жизнь» в краткой форме

1. В любой клетке может быть живая или мёртвая клетка.
2. Для каждой клетки считаются 8 соседей (по горизонтали, вертикали и диагоналям).
3. Живая клетка с 2 или 3 соседями выживает.
4. Живая клетка с менее 2 соседями умирает от одиночества.
5. Живая клетка с более 3 соседями умирает от перенаселения.
6. Мёртвая клетка с ровно 3 соседями рождается.
7. Все изменения происходят одновременно.

## 10. Заключение

Программа разбита на маленькие функции, каждая из которых отвечает за одну задачу:
- чтение состояния,
- подсчёт соседей,
- обновление поколения,
- отрисовку,
- обработку ввода,
- основной цикл.

Такое разделение соответствует принципам структурного программирования: сложная задача разбита на простые независимые части.
